# 会话删除 · dsh-session-delete

[English](README.en.md) | 简体中文

会话列表每一行末尾悬停时多一个垃圾桶；点它、确认一次，这一行连同磁盘上的会话目录一起消失。
目录不是硬删：它被送进 **Windows 系统回收站**，所以想找回还可以去回收站还原。

界面上只留两处：**行尾垃圾桶** 和 **顶部确认提示**。没有居中确认框，也没有插件内撤销按钮。

- 作者：Song-812
- 版本：0.1.1
- 许可证：MIT

## 怎么用

1. 鼠标移到左侧任意会话行上，行尾按钮条里最右边那个就是垃圾桶（排在 `⋯`、归档、置顶后面）。
2. 点它 → 顶部弹出确认提示：

   ```
   这条会话用了 812.7K token，删除吗？
                        [取消] [删除]
   ```

   默认焦点在「取消」上，回车不会误删；`Esc`、切换页面或关闭窗口时取消待确认的操作。

   如果**回收站不可用**（被禁用 / 配额满，由上一次真实删除观察到），问句会换成
   「回收站不可用：这条会话将永久删除、无法找回。删除吗？」——这话必须说在按下「删除」之前。

   如果**删前探测认为回收站可能不可用**（该卷配置了直通永久删除、或回收站查询失败），
   问句会换成「回收站可能不可用：这次删除有永久丢失风险，确定吗？」——比上面软一档：
   探测只是预警，删完对账的 permanent 才是铁证（两者同时在场时按铁证说）。
3. 点「删除」→ 那一行立刻消失（`api-session/removed` 广播，多窗口同步），不需要刷新。

删除成功后该行消失；失败时顶部提示检查会话列表和回收站。没有插件内撤销按钮。

只有会话目录被确认送进回收站，宿主才报告成功并广播移除。回收站桥只搬走了缓存、没有确认会话目录，或者失败原因不是「仅投影缓存仍在磁盘」时，按 `move-failed` 失败处理，列表那一行保持不动。仅投影缓存回收失败、且桥标明 `partial` 时，会话删除仍算成功，并记一条警告。

**删的正是当前正在看的那条会话**也可以：删除成功后会自动开一个空白会话，界面不会停在一条已经不存在的会话上。失败不会开空白会话。

## 两种情况删不了

按钮直接变灰、点不动，鼠标停上去写明原因：

| 情况 | 判断方 | 提示 |
| --- | --- | --- |
| 空白会话（磁盘上还没有目录） | 宿主复查 | 空白会话不用删，DSH 需要时会立刻再建一个 |
| 会话还在跑 | 宿主 `agents` 状态 | 会话还在跑，先停下来再删 |

「还在跑」的判定**只在本次悬停有效**：可删的结果会被记住，不可删的每次悬停都重新问宿主。
插件在鼠标悬停期间每 5 秒复核一次；拿得到 DSH 的 `api-session/status` 时还会立刻解锁。
所以回复一结束按钮自己变回可点，不用把鼠标移开再移回来。

> 空白会话之所以不许删：DSH 会为工作区按需保持一个空白会话，删掉之后它会以**新的 id**
> 立刻再冒出来，看起来就像「删了没生效」。

## 数据去哪了

| 东西 | 结果 |
| --- | --- |
| `%DSH_HOME%\sessions\<分桶>\<sessionId>\`（聊天记录、附件） | 送进 **Windows 回收站**（`SHFileOperationW` + `FOF_ALLOWUNDO`） |
| 工作区账目、归档集合里的这条会话 | 摘除 |
| `storages\session_projcache\sessions\<id>.json`（token 统计缓存） | 一起进回收站 |

找回：打开资源管理器回收站，选中那几项还原即可（还原后刷新 DSH 才会重新出现在列表里）。
**清空回收站 = 真没了**，插件不做第二份备份。

删除带 `FOF_WANTNUKEWARNING(0x4000)` 标志；删完还会**回头对账**回收站索引：
「离开磁盘」不等于「进了回收站」，只有原始路径真的出现在索引里才算可还原。
动手之前还会做一段**只读探测**（`binProbe`）：该卷 `BitBucket\Volume\{卷GUID}` 的
`NukeOnDelete` 配置 + `SHQueryRecycleBin` 查询，宿主据此判定 `binStatus`
（`ok` / `suspect` / `unknown`）——只读、任何异常都不阻塞删除。

## 宿主路由

| 路由 | 作用 |
| --- | --- |
| `POST /dsh-session-delete/check` | `{sessionId}` → `{deletable, reason, onDisk, total, label, permanent, binStatus}`；悬停时问禁用状态，点下去时问最终判定。`permanent: true` = 上次删除观察到回收站不可用，确认提示据此提前警告「将永久删除」；`binStatus` = 最近一次删除的删前探测结论（`suspect` → 确认提示预警「可能永久丢失」；还没删过是 `unknown`） |
| `POST /dsh-session-delete/delete` | 真删；被拒绝时 409 + `code: session-running / session-blank`（送回收站前会**复查**运行状态，两次检查之间会话被启动同样 409），回收站写不进去或会话目录未被确认移走时 500 + `move-failed`。响应含 `permanent`（删完对账回收站索引得出：true = 有内容被永久删除）与 `binStatus`（删前只读探测的结论） |
| `GET /dsh-session-delete/status` | 自检：home 路径、回收站桥写过没有 |
| `GET /dsh-session-delete/ping` | 连通性探针 |

## 开发

```bash
cd session-delete
node --test
```

`node --test` 会跑纯函数（token 格式化 / 删除判定 / id 形状 / 确认话术）、删除流程（TOCTOU 复查 / permanent 透传 / 桥的部分失败）和顶部确认提示。无 `powershell.exe` 时，依赖回收站的用例会 **skip**；有 PowerShell 时桥失败会让测试变红。

`test/bridge-roundtrip.mjs` 是手工往返：建临时文件 → 删除 → 还原 → 清理。它也位于 `test/` 下，因此会被 `node --test` 带上；没有 PowerShell 时脚本只记录桥调用失败并退出。

`test/confirm-toast.browser.mjs` 用本机 Chrome 检查顶部确认提示的焦点、Esc 取消和错误提示。找不到 puppeteer 时 **skip**。

安装：在 DSH 插件面板装本目录，或 `plugin_manager install_bundle` 指向包目录。
改了 `lib/client.js` 要刷新页面；改了 `lib/index.js` 要重新启用一次插件行（或重启）。

桥脚本内还保留 `restore` / `detect` 动作，**仅供手工排障**，插件 UI 与宿主路由都不暴露它们。

## 已知限制

- **只在 Windows 上能用**：回收站桥要 `powershell.exe` 调 `shell32.dll`。别的平台会直接报错，不会偷偷改成硬删。
- **回收站被禁用/配额满时，删除会静默变成永久删除**（Windows 的行为）。插件现在有两道防线：
  ①删前**只读探测**（卷的 `NukeOnDelete` 配置 + `SHQueryRecycleBin` 查询）——探测到可疑就提前
  预警「可能永久丢失」；②删完**对账索引**如实上报 `permanent`——确认提示升级成「将永久删除、无法找回」。
  但探测跟着删除流程走：**第一次**永久删除仍然发生在探测落地之前，那一次没有预警；从它之后
  每次删除前都会带上预警。成功回收一次后 permanent 提示自动解除。
- 只处理左侧会话列表里的常规会话行；工作区行没有这个按钮。
- 删当前正在看的会话会自动开一个空白会话；如果那一刻 DSH 自己也在切会话，可能会多开一个空白会话。
- 回收站有配额，系统自动清理时可能先删掉最旧的条目。
